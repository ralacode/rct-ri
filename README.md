# RCT（RI 業務支援アプリ）

RI 検査室・放射線治療の業務を効率化するデスクトップアプリです。
1 台の PC で起動したアプリが院内 LAN 向けの Web サーバーを兼ね、ほかの端末からはブラウザで同じ画面を使えます。

## 主な機能

| 区分 | 機能 |
| --- | --- |
| RI | 検査一覧（日ごとの検査オーダー・放射性医薬品使用記録簿の印刷・標識手順書）、減衰計算、ジェネレータ溶出記録の印刷、放射性同位元素使用室の作業内容記録の印刷 |
| 放射線治療 | 治療依頼表（枠ごとの治療依頼、RIS の CSV・Excel 取り込み、`ris/rt_order` に置いたファイルの自動取り込み） |
| 共通 | 患者の登録・一覧・検索、作業報告書（メーカーの保守・修理の報告。PDF の読み取り、`import/work_report` に置いたファイルの自動取り込み）、動画、質問・要望 |
| 管理 | 担当者管理、依頼科・依頼医の管理、設定（施設名） |

- 担当者ごとに「担当モダリティ」（RI・放射線治療・一般撮影）を割り当て、使えるページを絞ります。
- 担当者管理・依頼科と依頼医の管理・設定は、担当者管理権限を持つ人だけが使えます。

## 構成

- **画面**：Astro（静的出力）＋ React、Tailwind CSS（`src/`）
- **アプリ本体**：Tauri 2（Rust、`src-tauri/`）
  - 起動すると Axum の HTTP サーバーをポート `8080` で立ち上げ、ビルド済みの画面（`dist/`）と API（`/api/...`）を配信します。
  - アプリのウィンドウも `http://127.0.0.1:8080/` を表示します。
  - ほかの端末からは `http://<アプリを起動した PC の IP>:8080/` で使えます。
- **データ**：SQLite（rusqlite）。DB ファイルは実行ファイル（exe）と同じフォルダの `db/` にまとめて作られます。

### データファイル

| ファイル・フォルダ | 内容 |
| --- | --- |
| `db/rct_local.db` | 業務データ（患者・検査オーダー・治療依頼）と設定（施設名） |
| `db/requesters.db` | 依頼科・依頼医の一覧（入力候補） |
| `db/user.db` | 担当者・ログインセッション・担当モダリティ、動画のタイトルと視聴状況 |
| `db/feedback.db` | 質問・要望 |
| `db/work_report.db` | 作業報告書（装置・メーカー・作業担当者の一覧、添付した PDF・写真を含む） |
| `videos/` | 動画ファイル |
| `ris/rt_order/` | 治療依頼の Excel・CSV の置き場所（置くと自動で取り込まれます） |
| `import/work_report/` | 作業報告書の PDF・JSON の置き場所（置くと自動で取り込まれます） |

### 治療依頼の自動取り込み

アプリを起動すると、exe と同じフォルダに `ris/rt_order/` が作られます。ここに RIS の抽出ツールが出す治療依頼の Excel（`.xlsx`・`.xlsm`・`.xls`）か CSV を置くと、10 秒ほどで自動的に患者と治療依頼が登録されます。

- Excel は、患者ID・患者氏名・患者氏名カナ・性別名称・生年月日・身長・体重・検査予定日時・依頼科名・依頼者氏名の見出しがそろった行を、すべてのシートから探して表の始まりとみなします（上の抽出パターン名などの帯は読み飛ばします）。
- 予定時刻・カナ・重複の扱いは、治療依頼表の画面から読み込むときと同じです。すでに登録済みの依頼は飛ばすので、同じファイルをもう一度置いても重複しません。
- 取り込んだファイルは、取り込み結果（`.log.txt`）と一緒に移されます。
  - `取込済/`：すべての行を取り込めた（または登録済みだった）
  - `エラー/`：失敗した行がある、または治療依頼のファイルとして読めなかった。直してから `rt_order/` へ戻すと取り込み直します。
- Excel で開いたまま・コピー中のファイルは、閉じてから取り込みます。`~$` で始まる一時ファイルは無視します。

### 作業報告書

メーカーの作業報告書（保守・修理の報告）を保存します。ログインした人なら誰でも見て、登録・修正できます。

- 保存する項目：装置、件名、作業区分、作業指示番号、障害発生日時・到着日時・装置復帰・退出日時、作業内容、連絡事項、作業担当者（メーカー側。一覧から選ぶ・複数可）、担当技師（担当者一覧から選ぶ）、添付ファイル（PDF・写真）。
- **PDF の読み取り**：Varian（現 Siemens Healthineers）の電子署名付き PDF は、文字を読み取って項目を埋めます。VARIAN 時代と今の様式のどちらも読めます。一覧の「PDF・JSON を取り込む」から選ぶか、`import/work_report/` に置きます。
- **紙の報告書**：スマホの Claude アプリで写真を読み取り、決まった形の JSON にしてもらいます（指示文は作業報告書の設定画面からコピーできます）。JSON と写真（`報告書1.json` と `報告書1.jpg`・`報告書1-2.jpg` のように同じ名前で始める）を `import/work_report/` に置くと、写真を添付して取り込みます。
- 取り込んだ報告書は「要確認」として登録します。原本を横に見ながら確かめ、「確認済みにする」を押します。同じ作業指示番号の報告書は二重に登録しません。
- 装置は報告書の「納入商品」の番号で見分けます。報告書のメーカー表記が VARIAN から Siemens Healthineers に変わっても、同じ装置の履歴にまとまります。一覧にない装置・作業担当者は、取り込んだときに自動で登録します。
- 担当技師は報告書の「取引先責任者」（例: `Tsuzuki Shoya`）から判断します（署名は PDF の中で文字として読めないため）。ローマ字の表記は、一度報告書の画面で担当技師を選んで保存すると覚え、次からは自動で選びます。
- `import/work_report/` の取り込み結果は、`rt_order` と同じく `取込済/`・`エラー/` に `.log.txt` と一緒に移します。

バックアップでは、`db/` フォルダをまるごと（WAL モードのため、`-wal`・`-shm` ファイルも含めて）保存してください。

前の版で exe と同じフォルダに作られた `.db` ファイルは、起動時に `-wal`・`-shm` ごと `db/` へ自動で移されます（`db/` に同じ名前のファイルがすでにあるときは移さず、古いファイルはそのまま残します）。

## 初めて使うとき

アプリを起動してブラウザ（またはアプリのウィンドウ）で開くと、初期設定が始まります。

1. **初期管理者の作成**（初期設定 1 / 2）：最初の担当者アカウントを作ります。
2. **施設名の登録**（初期設定 2 / 2）：帳票に印字する施設名を登録します。

施設名を登録するまでアプリは使えません。施設名は、あとからサイドバーの「設定」で変更できます。

### 依頼科・依頼医

検査オーダーや治療依頼の依頼科・依頼医は、入力中に候補が表示されます。

- 一覧にない名前で保存すると、自動で一覧に追加されます。
- 名前の前後の空白は取り除かれ、続く空白（全角を含む）は半角 1 つにまとめられます。
- 打ち間違いなどは、サイドバーの「依頼科・依頼医」で修正・削除できます。
- 一覧の名前を変えたり削除したりしても、これまでのオーダーに記録された名前は変わりません。

## 開発

### 必要なもの

- Node.js 22.23.4 以上、pnpm 11
- Rust（stable）
- Tauri 2 の前提ソフト（OS ごとに異なります。[Tauri の Prerequisites](https://v2.tauri.app/start/prerequisites/) を参照）

### セットアップ

```bash
pnpm install
```

### アプリを起動する（開発用）

```bash
pnpm tauri dev
```

- 最初に画面をビルド（`dist/`）してから、Astro の開発サーバー（`http://localhost:4321`）とアプリを起動します。
- アプリのウィンドウは、ビルド済みの画面を `http://127.0.0.1:8080/` で表示します。
- 画面を編集しながら確認するときは、ブラウザで `http://localhost:4321` を開きます。`/api` へのリクエストは、起動中のアプリ（ポート `8080`）へ転送されます。
- 開発中のデータファイルは `src-tauri/target/debug/` に作られます。

### テスト

Rust のテストは、先に画面をビルドしてから実行します（Tauri のビルドに `dist/` が必要なため）。

```bash
pnpm build
```

```bash
cd src-tauri && cargo test --lib
```

### 配布用にビルドする

```bash
pnpm tauri build
```

- 実行ファイルと同じフォルダ（またはその `dist/`）に、ビルド済みの画面（`index.html` を含む `dist`）を置いてください。
- 見つからない場合は、起動中であることだけを示す簡易ページが表示されます。
- リリースビルドでは、OS の起動時にアプリが自動で起動するよう登録されます。
